# Web 演示计划：让外行看懂 Agent 记忆

## 演示目标

观众最终只需理解一句话：

> 它会从自然对话中逐渐了解用户、项目和过去经验，但每次只把当前任务真正需要、仍有
> 权使用的记忆交给模型。

页面和普通大模型产品一样：左侧对话，中间聊天，右侧“它记住了什么”。默认不讲
Embedding、RLS、Outbox 等术语；技术证据放在回答下方的折叠区域。

## 会前准备

建议提前 10 分钟完成：

1. 启动 PostgreSQL、Mem0、Qwen3 Embedding/Rerank 网关和 Memory Service；
2. 确认根目录 `.env` 权限是 `0600`，Kimi `k3` 配置有效；
3. 执行 `./scripts/demo-web.sh`，确认页面显示“真实链路已就绪”；
4. 确认 Memory Service 和 Web API 使用相同的 `DEMO_USER_ID=semantic-demo` 与
   `DEMO_PROJECT_ID=lazytt-memory-system-demo`；点击“重置演示数据”，同时清理隔离的
   User Scope、Project Scope 和演示对话；
5. 关闭含密钥、数据库密码和长日志的终端窗口。

打开 `http://localhost:3000`。服务均只绑定本机；Mem0 使用 `18888`，不会占用代理
软件常用的 `8888`。

## 8 分钟主讲脚本

### 1. 先建立直觉（1 分钟）

指向右侧空白记忆栏：

> 普通聊天只记得当前窗口。这里多了一层长期记忆，但它不会把每句话都保存；只有稳定、
> 安全、以后仍有用的信息才会形成正式记忆。

### 2. 一次自然介绍形成多类记忆（2 分钟）

点击“1 自然认识你”。消息会自然说明职业、技术栈、当前项目架构、一次 Outbox
经历和回答偏好，不使用“请记住”或固定口令。

请观众同时看三个位置：

- 回答按照偏好先给结论，再列要点；
- 右侧出现回答偏好、个人信息、项目信息和相关经历等多类卡片；
- 每张卡片明确显示“仅你可见”或“项目共享”；
- 回答下方能展开本轮实际注入的记忆内容、用途、来源与版本。

讲解：模型只提出候选，服务端决定允许的记忆类型和 Scope。个人信息不能被模型写到
项目空间；项目事实只有在当前身份具有项目权限、来源明确且置信度不低于 0.90 时才
自动接纳。普通记忆不会弹确认，保存后可随时撤销。

### 3. 新对话按需使用（1.5 分钟）

点击“2 跨对话使用”。页面创建新对话，只询问：

> 请根据你记得的我的工作角色、常用编程语言、LazyTT Memory 项目的权威数据库，以及我处理 Outbox 重复消费的经验，给我一份上线风险备忘；按我喜欢的回答格式组织。

用户没有重复具体职业名称、数据库产品和事故解决方法，但回答下方会列出本轮真正使用
的长期记忆。
讲解：网页中的聊天记录没有整段塞回模型；Context Pack 只选择与本轮问题相关且仍有权
使用的当前版本。

### 4. 项目事实自动更新（1.5 分钟）

点击“3 自动更新事实”。用户自然说明项目权威数据库从 PostgreSQL 改成 CockroachDB。
系统自动追加 v2、切换当前 Head，并显示“已自动更新记忆”的结果提示：

- v1 PostgreSQL 仍保留在版本历史中；
- v2 CockroachDB 成为当前有效事实；
- v2 在同一轮进入 Context Pack，回答立即按新事实生成。

讲解：页面不要求用户理解或处理记忆冲突。模型提出候选，确定性 Policy 检查权限、
类型、来源和置信度后自动更新；越权、密钥或低置信内容仍会被拒绝。展开右侧卡片可查看
v1/v2 版本链和审计证据。

### 5. 指定记忆立即忘记（1 分钟）

点击“4 自然忘记”。系统只停止使用“Outbox 重复消费经历”，职业、偏好和项目事实继续
保留；本轮回答的证据中不会再出现该经历。

讲解：PostgreSQL 先禁止读取，Mem0 投影随后删除，所以即使索引清理需要一点时间，
Agent 也已经拿不到被忘记的记忆。Forget 是精确控制，不会把其他长期记忆一并清空。

### 6. 用证据收尾（1 分钟）

展开回答下方“查看来源”：

> 这里直接展示本轮使用的记忆正文、类型、个人/项目范围、允许影响、来源数、版本、
> Context Pack、Outcome Receipt 和模型。我们展示的是系统真实状态，不是根据模型话术
> 猜测它好像记住了。

## 观众常见问题

### 它会偷偷记密码吗？

不会。Secret 检测、允许的记忆类型、置信度和 Policy 都在正式写入前；提取失败时
回答可以继续，但页面会明确说明没有声称保存新记忆。

### 模型能直接写正式记忆吗？

不能。Kimi Extractor 只产生不可信候选；Policy 与 PostgreSQL 事务决定是否接受。

### 为什么项目事实变化也不弹确认？

因为系统已经检查项目成员关系、写权限、明确来源、类型和高置信门槛。符合条件的新值
由受控 Policy 自动追加为新版本并提示结果；模型不能自行选择或扩大 Project Scope。

### 搜索到就一定会使用吗？

不会。Mem0 只是可重建目录。每个命中都回到 PostgreSQL 检查用户、用途、当前版本、
保留期、同意状态和 Forget/Tombstone。

### Forget 和 Erase 有什么不同？

Forget 是立即停止未来使用并保留审计链；Erase 是不可恢复地清理受保护正文与索引。

### 现在能直接生产上线吗？

不能。当前已经是可信的本地业务演示和集成参考，但生产仍缺外部身份/成员关系权威、
OIDC/JWKS、HA、灾备、容量压测、正式 tokenizer、告警和合规验收。

## 现场故障策略

- 页面显示链路未就绪：检查 `8080` Memory Service、`8090` Demo API 和 `18082`
  模型网关，不要临时改演示数据掩盖故障。
- Kimi 暂时失败：页面应显示终态错误；不要把旧录像说成现场结果。
- 仅需验证生命周期时，可使用仓库的 loopback 假模型，但必须明确称为“确定性备用模式”。

## 可以说与不该说

可以说：真实 Kimi 流式回答、四类记忆受限自动提取、User/Project Scope 隔离、当轮
写穿、去重来源合并、事实自动更新提示、版本链、Forget 零注入、PostgreSQL 权威和 Mem0
可重建投影均已在本机跑通。

不该说：已经生产可用、端到端 exactly-once、所有记忆类型均已成熟、已完成公网多租户
安全和灾备验收。
