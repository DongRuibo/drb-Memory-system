# 修复后网页复验清单

目标：确认浏览器里的按钮、回答和实际记忆快照相互一致。API 验证、构建成功以及修复前截图
均不能代替本清单。由用户在已经能够正常访问页面的对话中独立发起；不更改浏览器授权记录。

## 前置条件

- 代码工作区为 `/Users/drb/code/lazytt-memory-system/.run/resume-pgvector`；记录该目录的
  `git rev-parse HEAD`，不要把原仓库根目录另一分支的提交当作正在演示的版本。
- 页面为 `http://127.0.0.1:13000/`，左下角显示“真实链路已就绪”。
- 刷新页面，记录时间、演示身份、当前记忆数量、模型名称及代码提交。
- 保留现有 Alice/Bob 数据，不执行重置用户、重置项目或物理清除。
- 原共享数据库事实曾被测试清理误遗忘，现按同一 CockroachDB 内容恢复为新 v1 记录；
  旧 v1–v3 和误遗忘事件仍保留。参见实验收尾报告，不把恢复后的新版本号误判为历史被删除。
- 当前租户已有历史数据，结果应注明“已有数据复验”；不能冒充全新用户首次抽取。
  干净租户的原始整段抽取证据见 `scripts/verify-browser-regressions.py` 的 19 项真实回归。

## 必须逐步点击的六步流程

| 步骤 | 操作 | 验收标准 |
|---|---|---|
| 入口 | 点击侧栏“六步演示” | 创建“引导演示”会话，六个按钮可见；自由会话空白页的“开始六步演示”也应先建立引导会话。 |
| 1 | 点击“自然形成记忆”，等待完成 | 不拆句、不补录。职业与 Rust 分别为资料事实；项目权威数据库为项目事实；Outbox 为经历；技术回答格式为场景偏好。允许与旧记录合并或产生新版本，不要求固定条数。 |
| 2 | 点击“查看记忆结构”，展开相关卡片 | 类型、范围、结构化内容、事件时间、版本和来源可查看；普通事实不能被标为偏好。 |
| 3 | 点击“跨对话回忆” | 确实进入新网页会话；回答包含职业、Rust、项目数据库及经历。展开“本次使用了 N 条记忆”，逐项核对实际快照内容及版本。 |
| 4 | 点击“按时间回忆” | 不额外补 Outbox 关键词也能召回 2026 年 7 月经历；表达为下午，不得扩大为上午到下午。另开会话询问 2026 年 7 月 15 日上午，不应使用该下午经历。 |
| 5 | 点击“事实更新” | 当前数据库变为 CockroachDB，同一卡片保留先前 PostgreSQL 版本。另开会话提问时使用当前版本；历史已有 v3 等编号时不强行要求更新结果是 v2。 |
| 6 | 点击“忘记与清除” | 按钮执行指定经历的逻辑遗忘。另开会话分别用日期和 Outbox 关键词提问，实际上下文均不再包含该经历；项目事实和其他记忆保留。 |

每步等待本轮结束后再点下一步。仅凭回答“记住了”不能判定保存成功。
遗忘后允许其他仍适用的记忆（例如通用回答风格）进入快照，不能要求全部记忆一律为零。
同一对话中的原始消息仍存在，所以遗忘必须用新网页会话验证。

## 证据和结果格式

至少保留入口与六按钮、记忆分类、跨会话实际快照、事件时间、版本时间线、遗忘后快照的截图。
截图必须真实生成，记录本机绝对路径；失败时保留错误提示和触发前最后一步。

结果 JSON 应包含：

- `phase`: `after_fix`；时间、目标 URL、身份、代码提交和页面模型名称。
- 每项的 `result`（通过／失败／未测）、实际操作、观察结果、截图路径。
- 新会话证据以及实际使用的 record/version ID（可用页面显示前缀）。
- 是否执行过拆句补录、用户重置、项目重置、物理清除；本轮期望均为否。
- 最终保留的用户和记忆状态，以及尚未验证的边界。

将 JSON 和截图交回本项目验收记录后，才可将“修复后浏览器六步验收”改为通过。
若只能发送等价消息，仍可验证聊天能力，但按钮流程继续标为未测。
