# 简历项目条目：Agent 记忆治理系统

**技术栈：Rust / Axum / Tokio / SQLx / PostgreSQL / pgvector / Mem0 / Qwen3 / DeepSeek / React**

- 开发以 PostgreSQL 为权威账本的 Agent 记忆服务，使用 Mem0＋pgvector 维护检索投影；实现来源追溯、版本修正、冲突隔离与审核、Outbox 投递、权限回查和遗忘后的即时拒读。
- 区分通用回答风格、场景偏好、用户资料、项目事实和事件记忆；结合混合召回、候选排序、答案依据复核与时间精度约束，生成可审计的 Context Pack，支持跨会话回忆和事实更新。
- 建立固定集、失败回归与预先冻结的新场景验证：四组共 87 条正例、47 条负例，Recall@3／MRR 均为 1，负例零命中、遗忘后零注入；正例非目标候选比例均不超过 10%。159 项 Rust 测试及 21 项 PostgreSQL 集成测试通过。

## 面试时必须说明的边界

以上是当前单机、合成样本及 Qwen＋DeepSeek 复核配置下的观察，不是生产规模、完全确定性或泛化质量保证。Mem0 是投影适配层，治理由自研服务实现；向量／排序使用既有本地 Qwen 缓存，抽取／回答／适用性复核调用 DeepSeek。

固定集仍有 5%（1/20）严格标签外候选，另外三组为 0%。v1/v2 已作为回归集，新的 v3 是开发方编写、提前冻结的新场景验证，不是外部独立盲测；文档通过带类型 API 写入，不衡量新场景的自然语言抽取泛化。

真实链路另外通过聊天 19 项、适用性 16 项、抽取 22 项及范围事实／权限诊断 8 项。抽取包含归一化和有限的来源覆盖规则，不能把结果写成纯模型原始输出准确率。索引由 Outbox 异步更新，跨会话回忆验收明确等待投影就绪。

此前已有数据的浏览器六步复验通过（14 项、17 张截图）；本轮后端更新后完成的是 API／回答快照回归及本地部署核对，没有重新执行浏览器点击。原私有记忆的云端复验未获自动审批，未发送到 DeepSeek；模型实测使用合成数据。
