# Memory dev 配置清单

ECS 应用配置的唯一来源为 `/etc/lazytt/memory.env`，Bash `export NAME='value'` 格式，
`root:root 0600`；参考 [模板](.env.dev.example)。`release.py` 使用全新 Shell 显式加载，
按任务允许列表传入容器，不打印值。不依赖 `.bashrc` 或 ECS 工作目录的 `.env`。
新建材料前先核对管理员获准的已有来源；报告存在性、来源和配对状态即可。

| 变量 | 实际消费者／代码位置 | 默认与必填条件 | 敏感／来源 |
|---|---|---|---|
| `MEM0_POSTGRES_HOST`、`MEM0_POSTGRES_PORT` | Compose `POSTGRES_HOST/PORT` → 项目 `storage.py` 和 `database.py` | 迁移、配置、发布必填；目标 Store 实际可达地址/端口 | 否；Store 登记 |
| `MEM0_POSTGRES_RUNTIME_PASSWORD` | Compose `POSTGRES_PASSWORD` → Mem0／结构校验 | 同上；账号固定 `lazytt_memory_mem0_runtime` | 是；专用运行账号 |
| `MEM0_API_KEY` | Mem0 `ADMIN_API_KEY`、Memory adapter、显式配置器 | 配置/发布必填；至少 32 字节 | 是；Mem0 管理 API，禁止对 Agent 发放 |
| `MEMORY_JWT_HS256_SECRET` | Memory `auth.rs` | 配置/发布必填；至少 32 字节，两个认证秘密不能相同 | 是；需与获准签发方配对 |
| `MEMORY_JWT_ISSUER`、`MEMORY_JWT_AUDIENCE`、`MEMORY_TENANT_IDS` | Memory `auth.rs` | 配置/发布必填；租户为代码支持的逗号分隔 ID；不允许动态租户 | 否；身份负责人登记，不能用猜测的发行方 |
| `LAZYTT_MEMORY_HOST_PORT` | Compose 宿主机回环映射 | 完整配置必填；模板建议 18081，部署前检查占用 | 否；端口登记 |
| `LAZYTT_MEMORY_ELASTICSEARCH_ENDPOINT`、`ELASTICSEARCH_PORT` | 配置器 → Elasticsearch provider | 配置/发布必填；无凭据、无路径的 HTTP(S) origin，端口单独填写 | 否；Store 登记；私网 HTTP 需获准，HTTPS 必须验证证书 |
| `ELASTICSEARCH_USERNAME`、`STORE_ELASTICSEARCH_PASSWORD` | 显式配置器 → Mem0 持久配置 | 配置/发布必填；只允许 Memory 专用索引所需权限，不默认使用 elastic 超级账号 | 密码敏感；Store 管理员提供 |
| `ELASTICSEARCH_INDEX_PREFIX` | 配置器 `collection_name` | 必填；模板为 `lazytt-memory-dev`；不得接管既有未知索引 | 否；环境隔离登记 |
| `MEMORY_EMBEDDING_BASE_URL/API_KEY/MODEL/DIMENSIONS` | `release.py` 映射为 `EMBEDDING_*` → 配置器 | 配置/发布全部必填；公网模型使用 HTTPS；维度 1～4096 且须与真实输出相符 | API Key 敏感；Provider 配置 |
| `MEMORY_EXTRACT_BASE_URL/API_KEY/MODEL` | `release.py` 映射为 `LLM_*` → 配置器 | 配置/发布全部必填；公网模型使用 HTTPS | API Key 敏感；Provider 配置 |
| `MEM0_MIGRATION_PASSWORD` | 显式 migrate 时映射为 `POSTGRES_PASSWORD` | 仅 `/etc/lazytt/memory-migrate.env`；不进入应用文件、常驻容器或 GitHub | 是；本库 schema owner，非共享 PostgreSQL 超级账号 |

`APP_DB_NAME/POSTGRES_DB` 固定为 `lazytt_memory_mem0`；普通角色、B 模式、JWT 模式、
禁用动态租户、Mem0 内部地址和容器资源预算均在版本化部署文件中定义。
数据库角色连接上限为 8；项目侧 `storage.py` 使用 pool_size=3、max_overflow=2，每进程最多 5 个连接。迁移不与同系统发布并发。
Memory Service 的 B 模式不消费 `DATABASE_URL` 或根目录 SQLx Migration。
Elasticsearch 私有 CA 尚无本包专用注入入口：使用已可信 CA，或先审阅补齐信任链，不能关闭证书验证。

## GitHub Actions 配置

位置：仓库 Settings → Secrets and variables → Actions。仅配置发布连接信息，不上传应用秘密。

| 名称 | 类型 | 用途／值 |
|---|---|---|
| `ECS_HOST` | Variable | 已核验 ECS IP 或 SSH 域名，无协议和端口 |
| `ECS_PORT` | Variable | SSH 端口，如 22；不是 PostgreSQL 端口 |
| `ECS_USER` | Variable | 有 Docker/部署目录权限且能读取 root 配置的获准账号；当前脚本不自动 sudo |
| `ECS_REPO_DIR` | Variable | 独立绝对路径，建议 `/root/workspace/lazytt/lazytt-memory-system`；无需 Git checkout |
| `ECS_DEPLOY_ENABLED` | Variable | 缺失或 false：dev push 仅测试和构建；true：允许自动准备/发布；不停止现有服务 |
| `ECS_DEPLOY_ACTION` | Variable | `prepare`（默认，只交付）或 `release`（交付、等待管理员迁移、自动发布）；只影响 dev push |
| `ECS_MIGRATION_WAIT_SECONDS` | Variable，可选 | 等待数据库只读验收的秒数，默认 1800，允许 30～3600；超时保留候选，重跑原失败部署 job |
| `ECS_SSH_PRIVATE_KEY` | Secret | 专用部署账号私钥；配对公钥安装到该账号 authorized_keys |
| `ECS_KNOWN_HOSTS` | Secret | 独立核验的 host/端口/主机公钥；保持 StrictHostKeyChecking=yes |

镜像地址、digest、Git SHA 和 `GITHUB_TOKEN` 由 workflow 生成。构建 job 使用 packages:write，
部署 job 使用 packages:read。GHCR 包须允许本仓库 Actions 访问；不要求手填长期 PAT。
GitHub Runner 临时 SSH 文件、ECS 临时 registry 登录和发布辅助文件会在正常退出时清理。
ECS 的 `admin/<SHA>` 与 `database.sh` 是正式持久交付物，不能按临时文件删除。
主机掉电或强制杀进程可能留下 `/tmp/lazytt-memory-*`，恢复后核对归属再清理。

## Compose 变量与配置任务的区别

Compose 只把数据库运行连接、内部 API Key 和 Memory JWT/租户传入常驻服务。
ES、Embedding、聊天模型变量由 `release.py` 的允许列表映射到一次性配置任务，再经认证 API 存入 PG settings；
它们无需全部成为常驻容器环境变量。`MEM0_VECTOR_STORE_PROVIDER=elasticsearch` 和证书验证由配置任务固定，不能选择其他后端。
`MEM0_JWT_SECRET`、旧数据库容器密码、旧 CPU/CUDA profile、`MEMORY_POSTGRES_MODE` 已不是部署输入。

GitHub 只需手填上表 Variables 和两个 Secrets（SSH 私钥、known_hosts）；`GITHUB_TOKEN` 自动提供 GHCR 认证，
不要新增应用模型或数据库 Secrets。管理员完整填写本环境应用模板，再用独立 owner 文件执行迁移。

## 材料来源和交接方式

先复用管理员已授权的配置来源，不因缺少 ECS 参数重新生成已有密码或身份材料。
不知道目标时保留模板占位符；占位模板不能作为真实运行配置使用。

| 材料 | 向谁取得、核对什么 | 如何交接 |
|---|---|---|
| ECS 地址、SSH 端口和部署账号 | ECS 管理员提供实例连接信息和获准 Linux 账号；SSH 端口不等于 PG/ES 端口 | 非敏感登记可直接提供；随后填对应 GitHub Variables |
| 部署目录 | ECS 管理员确认专用绝对路径、目录归属，以及部署账号可使用 Docker、读取 root 配置 | 提供核验后的路径；不要把建议路径当成已存在的目录 |
| 部署 SSH 私钥及配对公钥 | 管理员核对专用密钥来源，公钥已安装到该账号 authorized_keys；当前脚本不支持私钥口令解锁 | 私钥直接写入 GitHub Secret `ECS_SSH_PRIVATE_KEY`；只反馈 Secret 名称和配置完成状态 |
| SSH 主机公钥 | 通过 ECS 控制台或既有可信连接核对主机身份，再与 host/端口匹配 | 核验后的 known_hosts 写入 `ECS_KNOWN_HOSTS`；不能仅凭未经核验的 ssh-keyscan 结果信任主机 |
| 已有 PG/ES | Store 管理员提供容器可达地址/端口、实际版本、数据库角色/权限、ES 专用账号及索引归属、证书信任链 | 非敏感连接登记可提供；运行密码由管理员填入 ECS 应用文件，owner 密码单独保存 |
| Memory 身份 | 身份负责人提供授权租户、issuer、audience 和配对的 HS256 签发材料 | 非敏感登记可提供；签名秘密直接进入 ECS 应用文件，不随意生成替代发行方 |
| 模型及内部 Mem0 Key | 模型负责人提供真实模型名、接口地址和 embedding 维度；管理员保管独立的 Mem0 服务 Key | 模型 API Key 和 Mem0 Key 直接进入 ECS 应用文件，不提供给 Agent |

提供连接登记时可以复制下面的非敏感清单，未知项写“待管理员确认”：

```text
ECS_HOST=
ECS_PORT=
ECS_USER=
ECS_REPO_DIR=
PG：版本 / 容器可达地址 / 端口
ES：版本 / 容器可达地址 / 端口 / 索引 / 证书信任方式
Memory：issuer / audience / 授权 tenant IDs
Embedding：base URL / model / 实际维度
提取模型：base URL / model
凭据：已配置的 GitHub Secret 名称；ECS 配置文件路径及准备状态
```

地址必须不含密码、Token 或认证查询参数。不要粘贴私钥、密码、API Key、签名秘密或完整 `.env`；
如已有受限本地文件需要核验，只提供文件路径和允许使用的范围，检查时只反馈存在性/格式/配对结果。
当前不需要立即提供这些材料；补齐后才能进行相应的 ECS 操作。
