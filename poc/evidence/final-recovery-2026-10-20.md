## 5. 最终核对发现并纠正的清理错误

最终指纹检查发现原共享数据库事实已被遗忘。审计事件定位到上个修复阶段
`2026-10-20T03:54:38Z` 的合成探针清理：清理客户端错误地带了原共享项目权限，
而旧 `Memory.cleanup()` 会遗忘导出中所有可见记录，把可见性误当成本次测试的所有权。
这是测试清理工具和调用配置错误；服务按该客户端持有的项目写权限执行了 Forget。

此前“原用户状态未变”的指纹比较只覆盖重启前后，发生在这次清理之前，不能据此声明
整个修复阶段都未改变原数据。这里更正该说法，没有修改历史指纹证据。

修复方式：

- 清理函数必须接收显式 record ID 白名单，写入前一次性验证 ID 存在且 scope 匹配；不再批量遗忘全部可见记录。
- 调用方跟踪创建操作返回的 ID，或在随机专用作用域中确认初始为空后仅清理新增 ID；更新适用性、性能、Episode 与最终评测驱动。
- 新增四项无云测试，覆盖可见共享事实保留、缺失白名单、未知 ID 和不匹配 scope；另以真实 API 验证同一可见共享项目权限下，只遗忘新建的个人测试记录，共享事实完整不变。

从原记录保留的 CockroachDB v3 内容与结构，经正常带类型写入接口重新入账，
Alice/Bob 均已验证能召回。原记录的 v1–v3、错误 Forget 事件和 tombstone 均未改写；
恢复得到的是**新的 active v1 记录**，不是把旧 v3 头指针或 revision 悄悄回滚。
旧版本仍可审计，页面当前记录的版本号因此会变化。本阶段没有重置用户、物理清除或回滚数据库。

详细证据为 `shared-project-recovery.json`、`cleanup-boundary-live.json` 和
