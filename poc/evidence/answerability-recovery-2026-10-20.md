## 修复内容

- 复核区分直接答案、任务约束和无关项。事实需要提供被问属性，场景偏好需要匹配任务；移除先前排序分数对语义复核的提示。原文证据检查、授权候选 ID 检查和失败时拒读保留。
- 时间依据使用有类型的内容引文／事件时间引用；时间精度由服务按实际查询窗口及时间问句决定，模型不能把“以前怎么做”自行解释成必须有日期。只有天粒度或未知日期的经历不能回答精确时刻。
- 增加带日期的小时、分钟、秒、下午 12 小时制、HH:mm 与整秒且带偏移的 RFC3339 解析。窗口为半开区间，10:30 的事件不会落入 10:31。时间过滤对经历生效；未来任务仍能使用稳定资料及场景偏好。类型依据来自 canonical 授权回查。
- 抽取侧将 global 标签限制到支持的全局回答风格键；饮食、代码和技术场景不因模型误标而全局注入，保留已有全局回答风格别名归一化。普通事实仍为 profile_fact／semantic_fact。
- 明确“描述当前已授权项目的事实”与“要求授予权限”的区别。对现有 `project.architecture.authority_store` 加入有限来源覆盖：只支持明确、唯一的当前数据库声明，受类型授权与候选数量限制，排除假设、疑问、引文、助手内容及不保存要求。该规则只覆盖两种中文声明形式及单个 ASCII 存储名称，不代表任意事实都能用规则补全；补充计入 coverage diagnostics。
- DeepSeek 抽取关闭思考并使用 temperature=0；Kimi 和通用兼容请求不添加这一字段。低温是本项目减少采样变化的选择，不是完全确定性的保证；参数语义见 [DeepSeek 官方 API](https://api-docs.deepseek.com/api/create-chat-completion/)。
- 验收驱动明确等待 Outbox 就绪，保存等待时长；开始写入前拒绝已有租户，清理只使用本次返回的 record ID。完整评测同时检查原 Release Gate 和额外精准性门槛，失败保留结果并非零退出。

## 保留失败与运行边界

[证据目录](answerability-recovery-2026-10-20/acceptance-summary.json) 保留初次偏好直接问答被误滤、分钟错配、未来偏好漏召回、无日期方法被误判、整段抽取漏数据库、接口事实漏抽取和饮食偏好误标 global 的记录；没有用后来的成功覆盖这些文件。

一次跨会话失败发生在请求创建后数据库事实才完成投影。保留操作完成时间与失败快照；修正的是验收的就绪前提，产品仍是异步索引，首次写入后不能保证立即跨会话读到。原文整段输入没有拆句或人工补录。

本轮只使用合成数据调用云模型。更新后本机 Memory API、Demo API 与 Web 均就绪，根端点确认复核 v6 与抽取 v7 已生效。原 Alice/Bob 的记录 ID、头状态、版本和 revision 指纹一致；Alice 仍有 8 条可用记忆，演示项目事实为 CockroachDB v3，指定 Outbox 经历仍处于逻辑遗忘状态。本系统实际权威账本仍是 PostgreSQL。

对原记忆进行云端检索复验被自动审批拒绝，原因是没有明确的数据披露授权；该搜索没有执行。最终改用本地健康、版本和账本指纹核对，不能将其描述为原记忆在新版本上的云端回答复验。所有合成测试记录按明确 ID 逻辑清理，未重置用户、物理清除数据、改写授权记录或推送 Git。
